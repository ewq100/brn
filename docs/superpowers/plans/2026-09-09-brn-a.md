# Capability A implementation plan: BRN service and terminal conversation client

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Draft, awaiting technical-plan user review. Do not start implementation until the user approves this plan and the parent has reconciled the governing GitHub issues (#21, #27, #33, #40). No implementation exists yet.

**Goal:** Stand up an independent foreground BRN service that hosts the pinned Pi SDK in-process, connect a small terminal conversation client over authenticated loopback HTTP/SSE, and complete a real conversation, proving service construction, tool/resource restrictions, session replacement, cancellation, reconnect, single-writer protection, and durable BRN operations.

**Architecture:** One private TypeScript package (Node 24, strict ESM, erasable syntax). `core/` holds pure domain types; `protocol/` holds browser-safe TypeBox contracts; `service/` holds the `node:http` server, single-instance lock, Pi adapter, and `node:sqlite` store; `cli/` holds the small line client. The service embeds the Pi SDK directly (no Pi RPC, no JSONL parsing) and exposes a BRN-owned HTTP/SSE contract.

**Tech Stack:** Node `24.20.0`, npm `11.19.0`, TypeScript `7.0.2`, `@earendil-works/pi-coding-agent@0.85.1` (+ `pi-ai`, `pi-tui` at `0.85.1`), `typebox@1.3.7`, `node:http`, `node:sqlite`, `vitest@5.0.0`, `@biomejs/biome@2.5.12`.

**Spec:** [docs/superpowers/specs/2026-09-09-brn-a-design.md](../specs/2026-09-09-brn-a-design.md)

## Global Constraints

Copied verbatim from #40 and brn-plan.md. Every task's requirements include these.

- Node `24.20.0`, npm `11.19.0`, TypeScript `7.0.2`. Record in `.node-version`, `engines.node: ">=24.20 <25"`, `packageManager: "npm@11.19.0"`.
- One root `package.json` and one `package-lock.json`. No npm workspaces. Strict ESM, `NodeNext` for Node code. No TypeScript enums, namespaces, decorators, or other non-erasable syntax on Node-side files.
- Pin every direct dependency exactly (no `^`/`~`). Commit `package-lock.json`.
- Pi exact pins: `@earendil-works/pi-coding-agent@0.85.1`, `@earendil-works/pi-ai@0.85.1`, `@earendil-works/pi-tui@0.85.1`.
- Local transport uses `node:http`, `URL`, Web Streams, `fetch`, `AbortController`, `crypto`. No Express, Fastify, Hono, SSE library, or HTTP client library.
- Persistence uses `node:sqlite` `DatabaseSync`, opened with extension loading disabled, foreign keys enabled, unknown named parameters rejected, defensive mode enabled. Startup verifies FTS5 and fails with a useful error otherwise.
- Product sessions start with all built-in tools disabled and load only BRN-controlled resources. No ambient extensions, skills, prompts, packages, settings, shell, or filesystem tools. Do not use Pi RPC or parse Pi JSONL.
- Never log credentials, tokens, cookies, prompts, record bodies, Inbox contents, or provider responses.
- Provider budgets: per-operation deadline 180 s; provider retries max 2; model catalog refresh bounded at 15 s. No automatic paid replay after restart.
- Real-SDK checks run offline (`PI_OFFLINE`, isolated config/session roots). The hermetic gate never calls a provider. One live-provider smoke test is opt-in behind an explicit env flag.

```typescript
// test/service/server.test.ts
import { mkdtempSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { afterEach, describe, expect, it } from "vitest";
import { openBrnDatabase, OperationStore } from "../../src/service/db.ts";
import { startBrnService } from "../../src/service/server.ts";

const lockDir = () => mkdtempSync(join(tmpdir(), "brn-lock-"));
let running: { close: () => Promise<void> } | undefined;
afterEach(async () => { await running?.close(); running = undefined; });

describe("startBrnService", () => {
  it("serves health only to authenticated loopback requests with the exact Host", async () => {
    const svc = await startBrnService({ store: new OperationStore(openBrnDatabase(join(lockDir(), "b.sqlite"))), lockDir: lockDir() });
    running = svc;
    const host = new URL(svc.url).host;

    const ok = await fetch(`${svc.url}/health`, { headers: { Authorization: `Bearer ${svc.token}`, Host: host } });
    expect(ok.status).toBe(200);

    const noAuth = await fetch(`${svc.url}/health`, { headers: { Host: host } });
    expect(noAuth.status).toBe(401);
    const body = await noAuth.json();
    expect(JSON.stringify(body)).not.toContain(svc.token);
  });

  it("refuses a second writer while the first holds the lock", async () => {
    const dir = lockDir();
    const store = new OperationStore(openBrnDatabase(join(dir, "b.sqlite")));
    const first = await startBrnService({ store, lockDir: dir });
    running = first;
    await expect(startBrnService({ store, lockDir: dir })).rejects.toThrow(/single writer|already running/i);
  });
});
```

- [ ] **Step 3: Write minimal implementation**

`acquireSingleInstance` writes an owner-only discovery file (`{ pid, port, instanceId, token }`) using an atomic create (`wx` flag). If the file exists, probe the recorded process/port: healthy means return `attach`; dead means reclaim after proving the pid is gone. `startBrnService` acquires the lock (throw if a healthy writer exists), binds `node:http` to `127.0.0.1:0`, generates a `crypto.randomUUID()` bearer token, and routes `/health` and `/ready`. Reject requests missing `Authorization: Bearer <token>` with a 401 `ErrorEnvelope` that leaks nothing. Require the exact `Host`. Emit no CORS headers. `close()` releases the lock and closes the server.
